# 人像工作室（3D Portrait Studio）實作計畫

> 草案 v2・2026-11-25・狀態：關卡 C 進行中——第一張照片的人像已加上眉毛，等你評估；眉毛完成（設計見第 15 節，實作紀錄見第 14 節）

## 1. 背景與目標

在 3D 導演台裡加一個**獨立的平行功能**：用參數做出寫實的 3D 人像白模（頭像、胸像、半身像、全身像）。

- 主要給 AI Agent 使用：Agent 拿到參考照片或一段文字描述，自己調參數做出人像；另外提供簡單的介面讓人類微調。
- 成品是可以在畫面上轉動檢視的靜態雕像（不需要動作、不需要材質），不會放進導演台的場景。
- 臉部要夠精細；臉型、五官位置與大小、胸部、身高、身形、頭身比例等特徵都要能用參數控制。
- 提供基礎預設（男性、女性 × 東亞、歐美），可以儲存與載入參數檔。

預期成果：參數化模型能做到「神似」，相當於肖像雕塑家依照片做的習作；不會是 3D 掃描等級的複製。

### 已確認的決策（2026-11-15）

| 項目 | 決定 |
|---|---|
| 基礎模型 | **MakeHuman 開放資產（CC0）**：官方寫實人體網格 hm08 與 1,274 個形變目標，調整引擎由我們用 TypeScript 自己寫。原本決定完全自製，第 0 階段做出的臉部效果不理想，關卡 A 時改用 MakeHuman |
| 風格範圍 | **寫實＋適度誇張**：以寫實人體結構為主，可推到約 4 頭身、放大眼睛等輕度漫畫感；不做 Q 版（2–3 頭身） |
| 頭髮 | **參數化雕塑髮型**：像石膏像的實心髮塊，約 8–10 種髮型，可調髮線、長度、分線、瀏海、蓬鬆度；男性另有鬍子 |
| 輸出 | 介面中轉動檢視，加上 **PNG 多角度渲染圖**與 **GLB／OBJ 網格檔**（不做 3D 列印前處理） |
| 照片量測 | **使用 MediaPipe 臉部特徵點偵測**（Apache-2.0，在本機瀏覽器執行，照片不上傳），只用來量照片，不是人像模型的一部分 |
| 表情 | **中性＋少數靜態表情**：微笑、嘴微張、挑眉、皺眉、瞇眼，強度可調、可疊加（不是動畫） |

### 預設做法（沒有另外詢問；不同意可以直接推翻）

- **整合方式**：同一個 App 裡的獨立頁面「人像工作室」（`/portrait.html`），共用伴隨伺服器、權杖與介面樣式。導演台工具列加一個入口，兩邊互不影響。
- **MCP**：另開一個 `portrait3d` 伺服器（背後是同一個伴隨伺服器），導演台的 `director3d` 工具清單不會因此變長。
- **座標與單位**：與導演台一致，Y 軸向上、人像面向 +Z、單位公尺；臉部量測用公釐。
- **姿勢**：靜態。全身像預設自然站姿（雙臂下垂），可改成 A 字姿勢；頭部可轉向、抬低、側傾；可加重心偏移（對立式平衡）。
- **身體**：不做衣物；用 MakeHuman 的素體（本身不含生殖器，胸部依參數）。
- **MakeHuman 資料**：原始資料下載在 `vendor/makehuman/`（不進版控）；轉檔後放在 `public/portrait/mh/`（約 37 MB，壓縮後約 17 MB），預設進版控，clone 下來就能用；`scripts/portrait-mh-convert.ts` 可重新轉檔。
- **眼睛**：雕塑風格；可選「刻出虹膜與瞳孔」，像古典胸像那樣讓視線有方向。
- **年齡**：先做成人（18–85 歲）；兒童與青少年在身體階段一起加入，因為頭身比與臉部比例都會跟著變。
- **第一版預設庫**：中性基準，加上男／女 × 東亞／歐美共 4 組；之後可以再加南亞、非洲等族群。
- **檔案位置**：人像存 `portraits/<id>.json`，參考照片存 `portraits/refs/<id>/`，輸出存 `exports/portraits/`。
- **介面語言**：繁體中文；API、參數鍵名用英文（與導演台相同）。
- **下載**：MediaPipe 的套件與模型到第 4 階段才下載，下載前會列出檔名、來源與大小請你確認。

### 不在這次範圍

材質、貼圖與彩色渲染；骨架動畫與動作；衣物；STL 與 3D 列印前處理；Q 版／動漫大頭；放進導演台場景；張嘴露牙（之後可加）。

## 2. 核心技術：MakeHuman 底模＋自寫的形變引擎

### 2.1 運作流程

```
人像文件（參數 JSON）
  │ 1. 語意參數（148 個）→ MakeHuman 修飾器數值、表情單位、姿勢、絕對身高與頭身比
  │    巨集：性別、年齡、族群、體重、肌肉、身體比例、胸部大小與挺度
  │    局部：臉型、五官、耳、頸、軀幹、四肢…（用到 170 個修飾器，含左右差目標）
  ▼
目標權重：巨集目標依類別權重相乘（例如 universal-女-青年-平均肌肉-高體重）
  │ 2. 基礎網格 hm08（13,380 頂點、全四邊形、封閉）＋ Σ 權重 × 形變目標
  ▼
絕對值反推：身高 → MakeHuman 身高巨集（再以整體縮放補足）；頭身比 → 頭部縮放
  ▼
骨架與蒙皮（MakeHuman 預設骨架 163 根骨頭，關節由變形後的網格重新計算）：
  自然站姿（手臂下垂）、頭部轉向／抬低／側傾、肩寬與肩斜、頭部縮放
  ▼
細分（Catmull–Clark，拓撲預先建好，每次只重算位置）：預覽 1 級、標準 2 級
  ▼
法線 → 胸像切割（胸部平切＋手臂斜切、補上平整切面）→ 雕刻眼球（隨頭部與視線轉動）
  ▼
三角網格 ─► 白模檢視／多角度渲染（three.js）
        ─► GLB／OBJ 輸出
        ─► 量測、特徵點、合理性檢查（拓撲固定，特徵點來自固定頂點組）
```

頭髮與底座（第 5、6 階段）用第 0 階段做好的 SDF 引擎（形體＋表面網格化）產生，再和身體合併。

### 2.2 為什麼這樣做

- **寫實度一開始就到位**：臉部與身體細節來自 MakeHuman 美術師做好的網格與形變目標。
- **拓撲固定**：每個頂點的意義不變，特徵點、量測、照片擬合都可以直接對應到頂點索引；局部修飾器對頂點位置是線性的，擬合時可以用最小平方法一次解出。
- **計算很快**：形變＋細分＋胸像切割全部在主執行緒 50 ms 內完成，拖滑桿即時更新，不需要 Worker。
- **授權乾淨**：只用 MakeHuman 的 CC0 資料；程式全部自己寫，不使用 MakeHuman 的 AGPL 程式碼。

### 2.3 效能（Apple M3，單執行緒，`node scripts/portrait-bench.ts`）

| 項目 | 全身 | 胸像 |
|---|---|---|
| 細分 1 級 | 6–7 ms，13 萬面 | 11–16 ms，6.5 萬面 |
| 細分 2 級 | 17–19 ms，45 萬面 | 36–41 ms，18.5 萬面 |

（第 1 階段的數字，含身高反推、蒙皮與量測；用預設「男性・歐美」「女性・東亞」測。）資料載入、拓撲與特徵點索引建立約 70 ms，只在開頁時做一次。

## 3. 參數系統

### 3.1 參數的意義

- **局部參數**：數值 −1～+1（0 = 不調整），對應 MakeHuman 的「最小／最大」成對目標（必要時乘上係數，例如太強的目標縮成 0.55～0.6）；單一目標（臉型混合等）0～1。±1 大約是真人的極端值（**寫實範圍**）。
- **誇張範圍**：目標是線性的，可以外插到 ±2（每個參數各有上限）；介面滑桿預設只顯示寫實範圍，打開「誇張模式」才延伸；超出寫實範圍時檢查會提示「誇張」，超出上限會被限制並警告。
- **巨集變數**：性別 0～1（0 女、1 男，可連續）、年齡（歲）、族群三個比例 `base.eastAsian`／`base.european`／`base.african`（自動正規化，都沒給時為平均混合）；體重、肌肉、身體比例、胸部大小與挺度用 −1～+1，0 為平均。
- **絕對參數**（我們加上的）：`body.heightCm`（公分）、`body.headsTall`（頭身比）；不給（null）時為「自動」，由其他參數決定。身高用 MakeHuman 身高巨集反推，超出範圍時再整體縮放；頭身比用頭部縮放反推（以頸部上端為支點，閉式解後再在蒙皮網格上迭代修正），兩者同時給時都會精確達成（身高誤差 < 1 mm，頭身比誤差 < 0.01）。
- **左右對稱**：MakeHuman 的五官修飾器多半分左右（l-／r-），介面預設連動，可以解除做出自然的不對稱。
- **語意層**：參數鍵名用我們自己的（例如 `face.nose.width`），對應到一個或多個 MakeHuman 修飾器，附中文標籤、兩端的意義、單位與範圍；Agent 和介面只看到語意層，底層資料以後要換也不影響參數檔。打錯鍵名時會列出相近的參數。
- **姿勢與視線**：`pose.*` 用角度（度）；正值一律是「往人物自己的左邊」（轉頭、側傾）、抬頭、手臂張開。`face.eyes.gazeYaw`／`gazePitch` 讓眼球相對頭部轉動。

### 3.4 特徵詞庫

把常見的中文描述詞整理成「參數配方」，人和 Agent 都能直接套用，並可設強度；套完的參數仍可再調。例如：

- 臉型：鵝蛋臉、圓臉、方臉（國字臉）、瓜子臉、長臉、菱形臉、心形臉
- 眼：丹鳳眼、杏眼、桃花眼、細長眼、單眼皮、內雙、雙眼皮、深邃眼窩、下垂眼、上揚眼、眼距寬
- 鼻：高鼻樑、塌鼻、鷹勾鼻、蒜頭鼻、朝天鼻、駝峰鼻、小巧鼻、鼻翼寬
- 嘴與下巴：厚唇、薄唇、櫻桃小嘴、M 唇、微笑唇、嘴角下垂、戽斗、小下巴、方下巴、尖下巴、美人溝
- 其他：高顴骨、蘋果肌、法令紋、雙下巴、招風耳、美人尖、高額頭
- 身材：寬肩、溜肩、沙漏身材、梨形身材、運動員體型、纖瘦、豐滿、啤酒肚、長腿

詞庫是一份 JSON，可以隨時擴充。

### 3.5 預設與參數檔

- **內建預設**：中性基準、男性・東亞、女性・東亞、男性・歐美、女性・歐美。預設本身就是一份參數檔。
- **另存為預設**：把目前的參數（或只存某些群組）存成自己的預設。
- **載入參數檔**：開啟人像檔，或把 `.portrait.json` 拖進視窗；「套用參數」可以只套某些群組（例如只套臉、保留身材與髮型）。
- **混合**：把兩組以上的參數按比例混合（例如 A 的臉 60%＋B 的臉 40%）。

## 4. 人像文件格式

一個人像就是一份人與 AI 都讀得懂的 JSON（附 JSON Schema：`schema/portrait.schema.json`）。只列出有改動的參數，其他都是基準值，所以檔案短、好比對差異。

```json
{
  "format": "director3d.portrait",
  "version": 1,
  "id": "pt_k3v9x2ab",
  "name": "林小姐・胸像",
  "preset": "female-eastAsian",
  "params": {
    "base.sex": 0,
    "base.age": 28,
    "base.eastAsian": 1,
    "body.heightCm": 162,
    "head.shape.oval": 0.4,
    "face.eyes.spacing": 0.8,
    "face.eyes.tilt": 1.2,
    "face.eyes.lidCrease": -1.5,
    "face.nose.bridgeHeight": -0.4,
    "face.mouth.upperLip": -0.5,
    "expr.smile": 0.3,
    "hair.style": "bob",
    "hair.bangs": "straight",
    "pose.headYaw": 8
  },
  "framing": { "type": "bust", "cut": "rounded", "pedestal": "round" },
  "references": [{ "id": "ref1", "file": "refs/pt_k3v9x2ab/ref1.jpg", "note": "正面，微笑" }],
  "notes": "",
  "revision": 12,
  "createdAt": "2026-11-15T10:00:00Z",
  "updatedAt": "2026-11-15T10:42:00Z"
}
```

- ID：`pt_` 開頭，唯一且不會變；`name` 可以用中文。
- 格式有版本號與遷移機制（參數改名或拆分時舊檔仍能開）。
- 有伺服器時存成 `portraits/<id>.json`，Agent 可以直接改檔，開著的頁面會即時重載（成為一個可復原的步驟）；純網頁時存在瀏覽器 IndexedDB。

沿用導演台的設計原則：

1. **單一真相**：人像就是一份 JSON 文件。

## 7. AI Agent 介面

### 7.1 指令

| 指令 | 作用 |
|---|---|
| `portrait.set` | 設定參數 `{params: {"face.eyes.spacing": 0.8, ...}}` |
| `portrait.reset` | 把某些參數、某個群組或全部恢復成基準值 |
| `portrait.applyPreset` | 套用預設或參數檔，可只套某些群組 |
| `portrait.applyTraits` | 套用特徵詞 `{traits: ["丹鳳眼", "高鼻樑"], amount: 0.7}` |
| `portrait.mix` | 按比例混合多組參數 |
| `portrait.update` | 名稱、備註、構圖（類型、切口、底座、雕像尺寸） |
| `portrait.addReference`／`removeReference` | 管理參考照片 |
| `portrait.fit` | 依參考照片自動擬合臉部與表情（可先 `dryRun` 只看建議值） |
| `portrait.neutralize` | 把表情歸零，保留長相 |
| `portrait.randomize` | 依種子隨機變化（找靈感、測試） |
| `history.undo`／`history.redo` | 復原／重做 |

規則與導演台相同：一批指令是原子交易（全部成功或全部不套用），算一次復原；錯誤回傳 `{index, cmd, code, message, hint}`，整批失敗時一次列出所有錯誤；可用 `dryRun`；成功時回傳這批修改新出現的檢查問題，以及主要量測的變化。

### 7.2 MCP 工具（`portrait3d`）

| 工具 | 作用 | 需要開分頁 |
|---|---|---|
| `portrait_guide` | 讀 Agent 指南（可依主題篩選） | 否 |
| `portrait_list_params` | 參數清單：分組摘要，或指定參數的完整規格（範圍、寫實範圍、單位、視覺效果） | 否 |
| `portrait_list_presets` | 內建與自訂預設、特徵詞庫 | 否 |
| `portrait_list`／`portrait_open`／`portrait_new` | 人像檔管理；新增時指定預設 | 否 |
| `portrait_get` | 人像文件（只列有改動的參數，或完整解析後的值） | 否 |
| `portrait_run` | 執行指令批次 | 否 |
| `portrait_measure` | 量測：公分／公釐、比例、z 分數與文字描述（例如「眼距偏寬 +1.2」） | 否 |
| `portrait_check` | 合理性檢查：超出寫實範圍、五官穿插、頭髮穿模、構圖切到臉、不對稱過大… | 否 |
| `portrait_render` | 渲染圖：單一角度或多角度組圖；可指定焦距、燈光、材質；`landmarks: true` 標出特徵點 | 是 |
| `portrait_add_reference` | 加入參考照片（檔案路徑、網址或 data URL），並用 MediaPipe 分析 | 是 |
| `portrait_compare` | 照片與人像用相同角度與焦距對照：並排、疊圖、差異箭頭，附數值差異與建議參數 | 是 |
| `portrait_fit` | 依參考照片自動擬合 | 是 |
| `portrait_export` | GLB／OBJ（不需分頁）與 PNG 多角度圖（需分頁），存到 `exports/portraits/` | 依格式 |

唯讀工具標 `readOnlyHint`；需要畫面時，MCP 會自動啟動伴隨伺服器並用 Chrome 開啟人像工作室（與導演台相同）。另附 `PORTRAIT_AGENTS.md`（Agent 指南）與 `portrait3d-sculpt` 技能（工作流程、像不像的檢查清單、評估案例）。

### 7.3 Agent 工作流程

**從照片做人像**

1. 目測性別、年齡、族群 → `portrait_new {preset}`。
2. `portrait_add_reference` → 取得特徵點、頭部角度、表情估計、照片品質提示（太側、遮擋、模糊）。
3. `portrait_fit` → 自動擬合臉部與表情，算一個復原步驟。
4. 目視補上 MediaPipe 量不到的部分：頭髮、耳朵、脖子、身材。
5. `portrait_compare` → 依差異由大到小修正，重複 4–5（通常 3–5 輪）。
6. 需要中性表情時用 `portrait.neutralize`（保留長相、移除笑容）。
7. `portrait_check` → `portrait_render` 正面／3/4／側面三視圖驗收 → `portrait_export`。

**從文字做人像**

1. 從描述判斷基礎預設 → `portrait.applyTraits`（例：「鵝蛋臉、丹鳳眼、高鼻樑、薄唇、齊瀏海短髮」）。
2. 依程度詞（「非常」「略」）調整配方強度，再用具體參數補強。
3. 渲染三視圖，用 `portrait_measure` 的文字描述對照原始描述，自我檢查。
4. 修正、存檔、輸出。

### 7.4 照片量測與自動擬合（MediaPipe）

1. **偵測**：MediaPipe Face Landmarker 在瀏覽器裡找出 478 個臉部特徵點、頭部姿態矩陣，以及 52 個表情係數。
2. **對應**：挑約 100 個語意明確的點（眼、眉、唇的輪廓、鼻子、臉的外框），對應到基礎網格的固定頂點（拓撲固定，對照表只要建一次）。
3. **估計相機**：用人像的 3D 特徵點反推照片的焦距與頭部角度（Levenberg–Marquardt 最小化重投影誤差）。
4. **擬合**：固定巨集（性別、族群、年齡）後，特徵點位置＝基準＋Σ 權重 × 目標位移，對局部修飾器與表情單位都是線性的，用帶正則化的最小平方法一次解出（表情以 MediaPipe 的表情係數當起點）。證據不足的參數會留在 0 附近，不會亂跳。可以用多張照片（例如正面＋3/4）一起擬合，深度方向（鼻樑高度、臉的立體感）會更準。
5. **輸出**：建議參數、各部位殘差與信心度；照片的比例描述（例如「鼻翼寬約是內眼角距離的 1.15 倍，偏寬」）。
6. **限制**：正面到約 60° 側臉有效；純側面照只能目視比對；頭髮、耳朵、身體量不到；濃妝、遮擋、強烈表情會降低準確度。
7. **自我測試**：隨機產生人像 → 渲染 → 偵測 → 擬合 → 比對還原出的參數，不需要真人照片就能驗證擬合流程。

## 8. 輸出

- **PNG**：單一角度或多角度組圖（正面、左右 3/4、左右側面、背面，可加俯視）；可選透明背景；最高 4K；套用燈光與材質預設；轉台連續圖（例如 24 張）。如果需要，也可以沿用導演台現有的 MP4 編碼輸出轉台影片。
- **GLB／OBJ**：單位公尺，實際尺寸或縮放到指定的雕像高度；皮膚、眼睛、頭髮、鬍子、底座分成不同群組，含法線；標準（約 30–60 萬面）與精細（約 100–200 萬面）兩種品質。網格化在 Node 也能跑，所以不開瀏覽器也能輸出網格。

## 12. 風險與對策

| 風險 | 影響 | 對策 |
|---|---|---|
| MakeHuman 的「通用 CG 臉」 | 預設臉看起來彼此很像 | 預設庫與特徵詞多樣化；照片擬合大量使用局部修飾器；必要時加自己的補充形變 |
| A 字姿勢 | 胸像肩膀上聳、全身像不自然 | 第 1 階段用 MakeHuman 的骨架與權重擺成自然站姿 |
| 外插到誇張範圍時變形 | 形狀扭曲 | 誇張範圍限制在 ±2 內並提醒；隨機組合自動測試 |
| 資料大小 | 首次載入約 37 MB | 只在人像頁載入、從本機讀取（約 0.1–0.3 秒）；之後可改成壓縮檔 |
| 手部與全身細節 | 全身像的手粗糙 | 採古典雕像的放鬆手勢、手指併攏；關卡 D 確認 |
| 照片擬合的限制 | 側臉、遮擋、濃妝、強烈表情時不準；量不到頭髮、耳朵、身體 | 多張照片聯合擬合、表情估計；其他部位由 Agent 目視；預期「神似」而非掃描等級 |
| 族群預設的呈現 | 變成刻板印象 | 預設值取自公開測量資料的平均，只當起點；命名中性、可以混合 |
| 雕塑髮型的品質 | 看起來像安全帽 | 參考古典雕塑的髮束處理，用流向紋路與髮束分塊做出層次；每款都截圖檢查 |

## 13. 考慮過但沒採用的方案

- **完全自製的程序化模型（SDF 雕塑）**：第 0 階段實作並調整了 17 輪；引擎本身可用（保留給頭髮與底座），但臉部寫實度遠不如美術師做的網格，關卡 A 決定改用 MakeHuman。
- **FLAME 2023 Open（CC-BY 4.0）**：掃描統計的寫實頭部，但參數是統計主成分、不直觀，而且只有頭頸。
- **直接使用 MakeHuman 的程式碼（AGPL）**：不採用。只用 CC0 的資料，程式自己寫，避免 AGPL 的授權義務。

**實作中學到、會影響後續階段的事**

1. 空間篩選要考慮「之後的平滑融合」：後面的形體用大半徑融合時，前面的形體在更遠處仍有影響，只看自己的融合半徑會把它刪掉，造成破面。現在改成倒序掃描累計後續半徑（聯集與減去分開計算），測試確認篩選後的值和完整計算完全相同。
2. 唇線、人中這類細節需要 0.5–0.6 mm 的格子才不會鋸齒；身體用 1.5–3 mm 就夠。頭部細、身體粗的分區網格化最好提前到第 1 階段做，同時解決預覽速度和面數。
3. 比一格還薄的形體會破洞：凹槽要從外面往內刻，不能在表面底下挖出薄殼。
4. three.js 的 `scene.environment` 要用 `scene.environmentIntensity` 調亮度（材質的 `envMapIntensity` 對它無效），否則環境光會把白模照得一片平。

**合成測試（完成標準）**

- 做法：隨機臉（強度 0.7，四個預設輪流）→ 平光、85 mm 渲染正面與 32° 側面當「照片」→ MediaPipe 偵測 → 從原本的預設擬合 → 比較 15 個臉部比例（以瞳距為準）與真值。`window.portrait.fitSelfTest()`，對照圖：`exports/portraits/p4_fit_selftest.png`。
- MediaPipe 在 312 張校正渲染上全部找得到臉；純側面（90°）找不到。
- 結果（兩組亂數共 12 張臉）：特徵點中位誤差 3.3～4.3 % → 2.2～2.5 %；比例平均誤差 9.8 → 8.4 %（4 張）、9.6 → 9.35 %（8 張）。穩定變好的是臉的直向比例：臉高、中臉／下臉、下巴高度（少約 30～60 %），鼻翼寬也常變好；眼睛開合、上下唇厚、鼻子深度與鼻長、下顎寬沒有變好，有時變差。參數值本身沒有更接近真值：不同的參數組合可以做出幾乎一樣的外觀。
- 判讀：計畫沒有事先訂數字門檻，這裡照實報告——擬合能還原相機、把整體比例拉近，細節（眼、唇、鼻子深度）不可靠。白模沒有眉毛、唇色、虹膜對比，MediaPipe 在白模上本來就比在真人照片上不準，所以這個測試偏悲觀；真人照片的效果要在關卡 C 看。拿人像自己的渲染當照片時，特徵點誤差約 2.5 %，這是對應表本身的誤差水準。

**實作中學到、會影響後續的事**

1. 臉部外框如果和所有參數一起擬合，剪影會吻合，但會用錯的組合（例如雙下巴、臉部肉感）去湊，其他比例反而變差；不知道焦距時（沒有 EXIF），臉寬誤差甚至變成兩倍——透視和臉寬從單張照片分不開。所以外框擬合預設關閉，改成實驗選項（先用特徵點擬合全部，再只用外框調臉寬、下顎寬、下巴寬、臉頰豐滿）。比對畫面照樣畫出外框差異、量出臉寬與下顎寬的差異，交給人或 Agent 判斷。（關卡 C 補充：原因之一是耳前的外框點配到耳朵，已修正；修正後的重新評估見關卡 C 紀錄。）
2. 外框對應一開始把脖子算進下巴（某些角度脖子在最外側）；改成只用下顎線（下巴與兩側下顎角構成的平面）以上的點後，下巴外框的偏差從約 −2 % 降到 0 附近。MakeHuman 的蒙皮權重分不出頭和脖子上段，所以用幾何平面。
3. MediaPipe 在白模上讀到的表情不準（常讀成皺眉、瞇眼）；真人照片應該好很多，但用「照片的表情」前先看一下報告。
4. 擬合以目前的參數為起點，重複執行會一直往照片（連同量測誤差）移動；建議擬合一次，再看比對畫面手動修正。
5. 沒有 EXIF 時焦距用約 43 mm 當弱先驗，誤差大時會影響臉寬判斷；知道焦距時可以用 `portrait.updateReference {focal35}` 指定（手機主鏡頭約 26 mm、人像模式約 50～77 mm）。

## 15. 眉毛（設計，2026-11-25；已完成，實作紀錄見第 14 節）

### 15.1 為什麼現在沒有眉毛

- **底模沒有這個零件**：MakeHuman 的基礎網格（hm08）不含眉毛。MakeHuman 的眉毛、睫毛、頭髮都是另外的「代理物件」——貼在皮膚上的平面片加毛髮透明貼圖。我們只轉了基礎網格、形變目標和骨架，沒有下載這些零件；就算下載，貼圖片放在白色雕塑上只是一層薄片，看不出眉形。
- **我們也還沒做**：底模有的是眉骨和眉區的皮膚。現有 3 個眉參數（眉骨突出、眉毛高低、眉尾角度）用的是 MakeHuman 的眉區形變目標，動的是皮膚和骨頭，不是眉毛本身。原計畫把「眉毛浮雕」放在第 5 階段（頭髮，用 SDF 引擎），沒有細部設計；第 3.2 節規劃的 7 個眉參數只做了 3 個。
- **影響**：少了最重要的表情和辨識特徵之一；照片擬合時 MediaPipe 在白模上只能從眉骨猜眉毛位置，關卡 C 的眉毛區域誤差 8～10 %，是各部位最大。

### 15.2 試驗結果

- **網格密度**：眉毛區域的頂點間距：細分 0 級約 4 mm、1 級約 2 mm、2 級（標準品質）約 1 mm。
- **MakeHuman 的皮膚 UV 不能直接用**：上眼皮是另一塊 UV，接縫剛好穿過眉毛下緣；眉區的拉伸程度差到 3 倍。
- **臨時試驗**（只改畫面上的網格，沒有改程式和存檔）：在關卡 C 人像的皮膚上沿眉形曲線往外推 0.65 mm。看得出是眉毛，眉頭寬、眉尾細的形狀正確；但 1 mm 的網格讓下緣有細鋸齒，直接在網格上刻毛流會變成不規則的顆粒。對照圖：`exports/portraits/brow_mock_compare.png`。

### 15.3 做法（建議）

眉毛做成**皮膚上的淺浮雕**，不是另外的零件：

1. **眉毛座標**：在眉毛附近的皮膚建一張自己的 2D 座標（沿眉方向 s、橫跨方向 t，單位 mm），在中性臉上算一次、綁在網格頂點上（拓撲固定）；細分時跟著內插。所以臉型、表情（挑眉、皺眉）、轉頭都會自動帶著眉毛走。預設位置用解剖規則：眉頭在內眼角上方略內側；眉峰約在眉長 2/3（鼻翼經過虹膜外緣的延長線）；眉尾在鼻翼經過外眼角的延長線上；女性眉下緣略高於眶上緣，男性貼著。
2. **眉形**：由眉頭、眉峰、眉尾決定的曲線，加上沿線的粗細與濃淡變化，算出高度場 h(s, t)：下緣較清楚、上緣羽化，眉頭方鈍或漸淡，眉尾收細。
3. **兩層細節**：
   - 形體（所有品質）：沿法線推出 0.3～1.2 mm；高度場依網格間距先做濾波，去掉 1 mm 網格的鋸齒。
   - 毛流（畫面與 PNG）：在著色器裡依眉毛座標和毛流方向（眉頭往上、眉身往外略上、眉尾往外略下）畫刻紋的光影，任何放大倍率都清楚，不增加網格。
   - 精細輸出（第 7 階段，約 100～200 萬面，細分 3 級約 0.5 mm）：毛流直接刻進網格，3D 列印也看得到。
4. **不用 SDF**：淺浮雕要到約 0.3 mm 的解析度才刻得出毛流，太重，還要和皮膚融合；頭髮仍照原計畫用 SDF。
5. **不用 MakeHuman 的眉毛零件**：要另外下載、是貼圖片、樣式固定不能參數化。

- 特徵詞：一字眉、柳葉眉、挑眉、劍眉（改成也設定眉形）、八字眉、濃眉、淡眉、粗眉、細眉、眉頭方、眉距近／寬、「不雕眉毛（古典）」。

### 15.5 照片擬合

- MediaPipe 的眉毛點（每邊上緣 5 點、下緣 5 點）改成直接和參數化眉形的上下緣比對（像外框一樣，不用固定頂點）。實作後只自動擬合眉峰高度與位置（加上原有的眉高、眉尾角度）：MediaPipe 的眉毛輪廓只部分跟著眉粗、眉長，真人照片上眉頭稀疏時又會把眉頭定偏外，所以眉間距、粗細、長度、濃淡看比對圖手動調（見第 14 節）。
- 這些點從固定頂點對應表移出（那是在沒有眉毛的白模上校正的，也是關卡 C 誤差最大的部位）。
- 有了眉毛，MediaPipe 看白模的結果會改變：特徵點對應表要重新驗證（必要時重新校正）；合成自我測試也會更接近真人照片的情況。

### 15.6 實作步驟與完成標準

1. 眉毛座標與高度場（`core/mh/brows.ts`），接進建模流程（細分後、算法線前），濾波去鋸齒。
2. 參數、預設、特徵詞；每個參數做 −1／0／+1 掃描圖確認。
3. 著色器的毛流刻紋（檢視器與 PNG 輸出）。
4. 照片擬合的眉毛模型；重新驗證特徵點對應表、重跑合成自我測試；用關卡 C 的照片重新擬合眉毛。
5. 測試、`PORTRAIT_AGENTS.md`、MCP 說明。

- 規模：中。
- 完成標準：三個角度在預設燈光下自然、沒有鋸齒和破面；跟著挑眉、皺眉、轉頭；每個參數的掃描圖正常；關卡 C 照片的眉毛區域誤差從約 9 % 降到 4 % 以下；標準品質的建模時間增加不到 5 ms。
- 建議做成第 5 階段之前的獨立小階段：直接改善關卡 C 的神似度和照片擬合，技術也和頭髮不同。

### 15.7 不在這次範圍

- 睫毛：雕塑通常不刻睫毛，眼瞼邊緣的厚度已經表現出來；以後可以加「眼瞼邊緣厚度」參數。
- 鬍子、髮際線屬於第 5 階段；但「皮膚上的 2D 座標＋高度場」這個做法可以沿用到鬍渣、髮際線、唇線這類貼著皮膚的細節。
